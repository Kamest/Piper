Global agent

Describe the release. It plans the work and starts the sessions.

The Global agent reads your projects, writes the plan with its dependencies and starts one session per project, each in its own sandbox.

  • Starts sessions through Piper's tools, never by itself
  • Its own sandbox, without your project libraries

Review

See what changed before anything leaves the machine.

A Git window with branches, worktrees, history and side-by-side diffs. Commit with a generated message, push when you agree.

  • Worktrees per session
  • A transcript view with tool calls, failures and token usage
Tools

Files, databases and HTTP requests, next to the agent.

Edit the project while the agent works. Piper asks before you overwrite a file it has just changed, and marks the files the agent never sees.

  • Database client with SSH tunnels
  • .http request runs with environments
  • Remote access over your tailnet
Security

Every guard is a switch. You choose how often you are asked.

Each session sees only its project, never the files you excluded. On top of that, pick a preset or set single rules. What an agent does on its own is still written to the audit log.

How it works

A small daemon, a terminal host and one container per session.

piperdServes the GUI on 127.0.0.1, keeps state in ~/.piper and answers the agents' tool calls. A held call becomes a card.
ptyhostRuns on its own, so piperd restarts while every session keeps working.
holeStarts each session's container with only its project mounted, minus the excluded paths.
extensionsAnything specific to your environment lives outside the core, in an extension.py.
Quick start

From a clone to the first session.

macOS · Linux · WSL 2hole ≥ 2.1.0Docker or PodmanPython ≥ 3.10 · gitTaskClaude or ChatGPT account
$ git clone https://github.com/Kamest/Piper.git piper
$ cd piper
$ task piper:doctor   # what this machine still needs, each with its fix
$ mkdir -p ~/.hole && cp -n examples/hole-settings.json ~/.hole/settings.json
$ task piper:open     # starts piperd and opens the GUI

Then press + Session, pick a project, the agent and the task. The first start builds the sandbox image once. The user guide walks through installing hole, the first session and daily use.

Early release. Piper is used daily on macOS and Linux; WSL 2 is supported but less exercised. Expect rough edges and settings that still change between releases. What is known is in Known rough edges; questions go to Discussions.
